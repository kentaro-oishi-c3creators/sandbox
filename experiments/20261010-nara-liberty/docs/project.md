## 何を確かめたいか

「Snowflake → Tableauより、Snowflake → 奈良を歩く100人の自由の女神の方がおもろいのでは？」から始まった実験。Snowflakeはデータを蓄積・分析するサービス、Tableauはデータをグラフで見せる道具です。

目標は、データを空間・大きさ・速さ・状態へ変換し、眺めたり操作したりして理解すること。「触って、おもろいか？」を第一の判断基準にする。厳密なデジタルツイン（現実の状態をデジタル空間に同期したもの）を作る段階ではない。

10月9日の評価メモによると、リアル調の静止画1枚への反応は期待に届かなかった。動き、数、淡々とした日常の演出、技術と目的のギャップが面白さを生む可能性はあるが、まだ仮説。

## 今回のMVP

MVPは「最初に成立させる最小版」。ユーザーの今回の依頼に合わせ、まず奈良公園・春日大社周辺の雰囲気を作る。その上で、元企画の意図が伝わる簡単な女神の群れを追加する。

1. 森・広場・参道・鳥居・石灯籠・社殿・鹿がある、奈良らしい空間。
2. Three.jsを使い、ブラウザで回転・拡大縮小できる。
3. 女神0 / 1 / 10 / 100体を切替。移動の停止・再開と速さ調整。
4. PC幅・スマホ幅のChromiumで動作を確認。
5. 文書とコードをGitHubの独立実験フォルダに保存し、動いた版をデプロイする。

Three.jsはブラウザで3Dを描画するJavaScriptのライブラリです。今回はReactを使わず、画面と3D処理を直接つないで小さく保つ。

## 成功の判断と次の段階

技術的成功: 3D表示・全操作・100体の描画が動く。利用者の判断: 「奈良を感じるか」「止まっているより動いているほうが面白いか」「触ってまた眺めたいか」。AIだけの採点で面白いと断定しない。

次の順番は、本人の反応 → 配置・演出の調整 → 必要なら現地資料と地理データ → データを色・高さ・速さへ割当 → 必要ならSnowflake接続。笑い・興味・美しさは別々に観察する。
