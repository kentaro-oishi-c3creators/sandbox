# 検証結果

2026-10-10 日本時間。MVP初版の実行結果。

## 検証する体験

ページを開く → 3Dの奈良が見える → 数・速度・停止を変える → 女神の状態が変わる → 場所を切替えて眺める。外部APIやデータベースを使わないため、ブラウザ内の状態と描画を確認する。

## 初回確認と修正

初回のChromium検証では、PC幅1440×900とスマホ幅390×844で、WebGL2描画、100体表示、移動、停止、数変更、速度変更、視点切替、ドラッグ、視点復元、説明ダイアログ、横はみ出しなし、JavaScript例外なし、失敗リクエストなしを確認。

一方、個別描画の初期版は描画命令がPCで2,817回、ソフトウェア描画で1〜4 FPSと重かった。この版は公開せず、背景の結合と女神のInstancingを追加してから再検証する。

## 最終確認

- `npm run build`: 成功。JavaScript約544kB（gzip約141kB）。Viteから500kB超のチャンク警告あり。3Dエンジンを含むためであり、ビルドエラーではない。
- 最適化後の開発版、および `npm run preview` で配信した公開ビルドの両方をChromiumで検証。
- PC 1440×900、スマホ幅390×844: WebGL2描画、100体、移動、停止、0/1/10/100体切替、速度変更、3視点切替、ドラッグで回転、視点復元、説明ダイアログ、Escapeで閉じる、横はみ出しなしを確認。
- 動きを減らす設定: 初期停止を確認。
- JavaScript例外0件、失敗リクエスト0件。
- 描画命令: どちらの画面幅も64回。約66,152三角形。初期版に対して描画命令を約98%削減。
- ソフトウェア描画の公開ビルドはPC約1 FPS・スマホ幅約3 FPS。操作機能は通るが、この環境での滑らかさは十分ではない。実機GPUでの性能は未検証で、滑らかに動くことを保証する結果ではない。
- スクリーンショットと機械的な結果: 実験内の `test-results/nara-1440.png`、`nara-390.png`、`results.json`（Gitには追加しない）。
