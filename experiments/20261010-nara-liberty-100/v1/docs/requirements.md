# 要件定義 / MVP 0.1

2026-10-10。対象: 奈良の雰囲気を眺め、女神の数・動きを操作する人。Googleアカウントや開発知識なしでアプリを操作できること。

| 要件 | 完成の判定 |
| --- | --- |
| 奈良らしい空間 | 森、広場、参道、鳥居、石灯籠、朱色の社殿、鹿が3Dで見える |
| 視点操作 | マウスドラッグ・スクロール、タッチ操作に対応したOrbitControlsを使う |
| 3つの場所 | ボタンで公園・参道・社殿へ視点が移る |
| 女神の数 | 0 / 1 / 10 / 100体を切替し、表示数が一致する |
| 動き | 個体ごとに異なる速さで移動し、足が揺れる。範囲の終端でループする |
| 停止・再開 | 停止中に位置が変わらず、再開で移動が戻る |
| 速度変更 | 0.2〜2.0倍の入力が移動時間に反映される |
| 操作説明 | 日本語の説明、参照元リンク、簡略再現である旨を表示 |
| 小さな画面 | 幅390pxで設定・場所切替が使え、横にはみ出さない |
| エラー表示 | WebGL初期化失敗・描画中断を日本語で知らせる |
| 動きを減らす設定 | OS・ブラウザのprefers-reduced-motionでは初期停止、視点切替は即時 |
| 再開可能性 | 依存バージョンを固定し、起動・確認・公開方法を文書に残す |

## 今回の範囲外

実測の地形・道路・建物再現、観光案内、高精度歩行、衝突回避、物理演算、ログイン、個人情報保存、外部データベース、Snowflake接続。女神の群れは互いに衝突せず通過する。移動は簡易ループで、実際の歩行経路のシミュレーションではない。

## 性能と対応

WebGL2対応ブラウザを対象とする。100体は同じ形をまとめて描くInstancing（同じモデルを効率よく複数表示する方式）で実装。背景は素材別に結合する。画面解像度の倍率は最大1.6倍に制限。

FPSは1秒に何枚描画できるかという滑らかさの目安。今回のChromiumはソフトウェア描画であり、実機GPUの性能評価ではない。PC・スマホの実機、Safari、タッチ端末の体感速度は別途確認する。

キーボードで設定ボタンや数・速度を操作できる。3D空間自体のキーボード散歩は未実装。完全な視覚代替体験は今回の範囲外。
