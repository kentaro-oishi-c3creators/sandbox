# V2 企画・要件・仕様・環境

## 企画

元企画は「奈良を100人で歩く自由の女神」。巨大な異物のシュールさを際立たせるには、背景に現実らしい日常が必要。V2では女神を外し、春日大社の短い参道体験を評価するMVP（最小限の試作品）とする。[元資料](references.md)と[V1レビュー](v1-review.md)が企画の根拠。

## 完成範囲と受け入れ条件

1. 道路入口→一之鳥居→森の参道→橋→二之鳥居→石段→南門の順で歩ける。
2. 人の目線1.65mを保ち、地形に沿って上下する。南門の高さは地面から12m。
3. 石灯籠、苔、砂利、樹皮、木立、朱色・白壁の建築を手作りの材質と形で表現する。
4. PC・スマホ幅で歩行、停止、視点、地点移動、俯瞰、リセットが使え、JavaScript例外や通信失敗がない。
5. 鹿・人・女神を含めない。V1のフォルダと公開先を保持し、V2を別公開先で比較する。

「見た人が本物の春日大社だと感じるか」は人による評価事項。操作テストの合格だけで写実性が達成されたとは扱わない。

## 空間仕様

Three.jsの1単位を1mとして扱う。現地順序を参考に編集した約241.18mのルート。緯度経度・測量データとは対応しない。二之鳥居以降の森林・灯籠・石段と南門の表現を重点にする。南門まで到達して止まり、境内内部の完全再現は行わない。

南門は二階建ての楼門、朱色の柱、白壁、上下の屋根、回廊を構成。モデルの頂点範囲から高さを測り12mに調整。鳥居など他の寸法は推定。歩行の最後は屋根を見上げる角度へ緩やかに変える。俯瞰地図はルートの模式図で、位置案内用ではない。

## 技術と構成

Reactを使わずJavaScriptとThree.js 0.180.0で構築する。画面部品が少なく、3D処理を直接管理しやすいため。Vite 7.1.9は開発サーバー・配信ファイル生成に使用。playwright-core 1.56.0は本物のChromiumを操作する確認用。

| ファイル | 役割 |
| --- | --- |
| `index.html` / `src/style.css` | 操作画面、説明、スマホ配置 |
| `src/main.js` | 描画、カメラ、歩行、入力、画質 |
| `src/route.js` | 編集ルート、地点補間、地面高さ |
| `src/world.js` | 森、灯籠、鳥居、橋、石段、門 |
| `src/textures.js` | 独自に生成する表面模様と葉 |
| `tests/browser.mjs` | PC・スマホの操作と描画の検証 |

外部写真・3Dモデルを配信素材に使用しない。表面模様はCanvas（ブラウザで絵を描く機能）で生成する。静的な模型を材質ごとにまとめ、葉はInstancing（同じ形をまとめて描く手法）を使用。影は固定し、カメラが動かないときは描画を休止する。音声・バックエンド・保存機能はない。

## 公開・運用

独立したVercelプロジェクト `kasuga-forest-v2` に公開。ビルドは `npm ci` → `npm run build`、配信フォルダは `dist`、Node.js 24.x。V1の `nara-liberty-100` は保持。認証設定は保持し、必要時に期限付き共有リンクを作る。リンクの認証用文字列をGitへ保存しない。

今回の公開は接続ツール経由のソースアップロード。GitHub変更のたびに自動公開される設定は作っていない。更新時は動作確認後に再デプロイし、ソースのコミット番号と公開先を記録する。

## 残る課題

写真のピクセルを比較する照合、地形と建築の実測、現地の細かな樹木・灯籠配置は未実施。現在は手作りの再構成として評価する。高精細モードや低性能端末では描画が遅くなる可能性がある。実機スマホのGPU（描画用の部品）での速度は未測定。
